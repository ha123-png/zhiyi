# v0.4.0 原文件归档

选择模板高级设置中的“原文件归档”并保存，就是启用归档；没有额外确认框。此前已完成的对话模型恢复、说明直接展示、本地按原口径重新分析、币种文案与图表轴间距修正一并保留。

## 用户能看到的变化

- 原文件处理可选不处理、移动归档、复制副本。旧复制设置保持原行为。
- 在桌面版通过“选择文件”导入，结果保存成功后才移动原位置的文件。内部原件继续保留，仍可预览、重新提取和备份。
- 同名、占用、权限不足等问题进入现有待处理事项。概览只显示名称、原因、状态和“处理”，弹窗内修改归档名称或位置、重试、跳过。
- 归档未完成时不计入已完成列表；完成或跳过后才进入最近完成。处理日志区分归档和复制。
- 浏览器上传、拖入和粘贴不提供可核实的原路径；需要归档时请使用桌面版“选择文件”。网络位置、链接及云盘占位文件仍可提取，第一版不移动这些文件。

## 文件保护方式

本地文件选择器签发一次性的短期导入凭证，网页及模型不能向接口提交任意原路径。导入时保存文件身份、大小、修改时间和完整摘要，来源路径不进入任务公开详情或模型工具。

移动前核对原文件身份和内容。先在目标磁盘暂存、校验并发布完整文件，再通过 Windows 文件句柄移除原位置的文件；目标与相关文件夹在关键步骤受到操作系统的共享访问约束，不能被另一个进程偷偷替换。目标发布始终不覆盖现有文件。

跨盘文件操作和数据库提交不是一个原子事务。知意记录暂存、发布和移除阶段，中断后核实记录再继续；如果原位置移除失败，保留文件并进入待处理，重试复用已核实的目标。不会关闭系统防护、调整目录权限或自动提权。

恢复业务备份后关闭自动文件处理，清除外部原文件移动权限，未完成归档进入待处理，不会继续删除备份里记录的旧来源。归档完成后，外部文件由用户管理，知意不追踪其改名或移动，也不会重新生成。

## 已完成的验证

- 后端完整回归 750 项通过；前端完整回归 170 项通过。
- Windows 真实文件操作覆盖同名冲突、改名重试、源文件内容变化、同内容替换、文件占用、删除权限受阻、目标被替换、一次性凭证、浏览器无移动权限、恢复备份不继续移动。
- 在暂存、发布目标、移除原位置三个阶段，独立子进程直接退出，恢复后完整文件仍在且未重复生成。另覆盖异常退出前后的提交恢复。
- 磁盘写满采用写入失败注入，没有填满用户磁盘；原文件保留，可换路径重试。
- C 盘至 D 盘实际归档 16,777,397 字节：只读原文件保留，解除测试文件的只读属性后重试成功，复用同一目标文件；完整 SHA-256 一致。
- 浏览器实际执行同名冲突改名重试，待处理项减少、最近完成增加；长文件名不挤压标签，弹窗没有第二次确认。截图和逐项结果保存在本地验收目录。

最终安装包另做启动停止、完整升级生命周期、原口径一万条统计刷新、归档链路与已安装业务数据校验。具体包摘要、路径和安装后结果以发行目录中的交付记录为准。本轮不推送公开仓库，不创建 GitHub Release。

上述有界测试覆盖常见故障及进程中断，不等于任意硬件断电、损坏磁盘或无限数据量保证。

实现依据：[Windows 文件共享访问](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)；[按句柄设置文件移除状态](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)。
