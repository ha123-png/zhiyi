# 知意

知意是一款把非结构化文件变成可核对、可追溯、可继续使用的结构化数据的本地工作台。模板表达你想理解什么，模型负责阅读与提取；确定性规则和人工核对共同把关。

> 当前版本：`v0.5.0`，Windows x64。版本变化见[0.5.0 版本说明](docs/版本说明/v0.5.0.md)，首次升级前请阅读[升级使用说明](docs/升级使用说明.md)，特别是本版的数据模型变化与回退边界。

## 设计哲学

**知意，是“知道意思”，不是“识别文字”。**

大多数文档工具把文字从图片或文件里取出来；“它是什么意思”仍要人来判断。知意用一套**微型指令集**表达你需要的字段、语义和规则，让通用多模态模型理解内容并生成结构化结果，再由程序校验、人工核对。

- **通用，而非专用：** 错题本、作业批改、发票、送货单、资料整理都可以换一套字段要求，不依赖为每种文件预置识别模板。
- **模型自由，而非本地优先：** 本地模型守住数据边界，云端模型可换来更快或更强的能力；同一条工作流按任务选择。使用云端服务时，本次请求涉及的文件内容会发送给你配置的服务商。
- **可信，而非“模型保证”：** 正确性来自规则校验、人工核对和来源追溯，不依赖模型一句“我猜的”。

**原件是证据，当前数据是事实，修订历史解释变化。**同一个文件的当前值只有一份，文件详情和数据仓库是两个工作入口；仪表盘、问知意、导出和接口读取相同的当前值。模型输出可能有误，重要数据仍应对照原件人工核验。

## 它能做什么

### 从发票与送货单开始，也可以换成你的字段

不同商家的单据版式各异，手写内容也常见。知意让模型结合字段含义和业务提示理解内容，再把结果按你定义的结构整理出来。发票和送货单是可修改的示例模板；错题本、作业批改、新闻整理等也可以用自己的字段模板完成。

模板不是一套预训练识别器。你可以自己定义字段、类型、文件级与明细字段、规则和读取要求，也可以让 AI 根据样例起草，再核对和编辑。对临时资料或字段各异的文件，可以使用“自主提取”，让每份文件独立决定结构。

### 从一份文件开始

1. **连接模型。** 使用已经安装的 LM Studio、Ollama，或配置兼容云服务。知意安装包不捆绑模型。
2. **定义理解要求。** 选择模板或“自主提取”，检查字段、读取范围和确定性规则。
3. **上传并提取。** 指定文件和模板，或使用智能匹配；拿不准时由你选择。
4. **对照原件核对。** 有疑问就修订或处理校验问题。入库不等于已经人工确认正确。
5. **继续使用。** 在数据仓库搜索、筛选、编辑、统计与导出；需要时从问知意或受限接口读取同一份当前事实。

## 主要能力

| 能力 | 可以怎样使用 |
| --- | --- |
| 模板与理解要求 | 自定义字段、类型、文件抬头和明细，补充业务提示；AI 可结合需求和样例起草字段与规则。示例模板可以复制、修改和删除。 |
| 智能匹配与自主提取 | 从你选定的模板中匹配，拿不准时交由人工选择；也可让每份文件独立决定字段结构。 |
| 提取与核对 | 批量排队、暂停、恢复和重试；对照原件修正结果，结合必填、范围、枚举、格式和计算规则检查。 |
| 文件名与原文件处理 | 按 AI 建议或固定规则命名；可选择原文件归档或复制副本，冲突进入待处理。内部原件独立保留。 |
| 数据仓库与来源 | 表格和卡片读取同一份事实；可搜索、筛选、编辑、分组、导入、合并和导出，并查看来源与文件修订。 |
| 仪表盘与问知意 | 仪表盘由程序计算当前数据；问知意在授权资料范围内查找、统计、绘图、解释依据，修改先预览再确认；授权或数据变化后过期预览不能继续执行。 |
| API / MCP | 默认关闭；可按能力开放限定目录文件导入、任务控制、查询、修改和导出，事实行修改带版本检查。 |
| 备份与桌面运行 | 完整备份与恢复业务记录及内部原件；单实例运行，普通卸载默认保留本地业务数据。 |

## v0.5.0 的工作流改进

本版围绕已有工作流收敛文件、数据、权限和操作状态：文件详情、文件历史与数据仓库的预览、修订、确认和冲突反馈保持一致；并发写入被拒绝时，界面重新读取当前事实，并将未保存输入单独保留，避免把旧值显示成已保存。

问知意会受当前资料范围和操作授权约束；修改先形成可检查的预览，确认后执行。授权撤销、范围变化或底层数据变化会让旧预览过期，重新授权也不会让旧方案复活。原件删除和迁移使用路径与内容校验；清理失败保留待办，可在后续启动重试。备份恢复验证归档和原件摘要，暂存迁移失败时保留正在使用的数据。

## v0.5.0 的数据模型与升级兼容

v0.5.0 是一次重要的数据模型调整。v0.4.0 将文件提取/核对结果与数据仓库行分别保存，它们可以各自变化。v0.5.0 增加唯一的 `file_current_data`，保存每个文件当前的文件级字段、结构、校验状态和版本；`data_rows` 继续保存明细。提取与核对记录保留为来源证据，`file_revisions` 记录当前事实的变化。文件详情、仓库等入口不再各自维护“当前值”。

**为什么会有“旧数据冲突”？**例如，同一张单据提取时金额是 100 元，后来只在数据仓库改成 120 元，文件详情中仍然是 100 元。v0.4.0 可能分别保留这两个值；v0.5.0 共用一份当前数据，程序无法知道你最终认可哪一个。这里的冲突指同一信息的旧值不一致，不是文件重名或重复上传。

两处值一致、结构可以明确转换的旧数据可以自动迁移，保留对应明细身份、原件与旧记录；无需重新调用模型。遇到值不一致、字段归属不清或无法确认数据是否曾被主动清空时，**整个本次迁移会停止，不会跳过问题文件，也不会擅自选一边覆盖**。当前没有原地冲突合并界面。

因此，**本版支持无歧义旧数据的自动迁移，不承诺任意 v0.4.0 旧库都能直接升级。**升级前请在 v0.4.0 的“备份”页创建并另存完整业务备份。迁移停止时保留旧环境；另建新版工作区重新导入不能自动恢复旧版人工修订与附加信息，需要另存并核对。新旧数据库、备份和修订结构不能直接混用，不支持原地降级。完整解释及处理步骤见[升级使用说明](docs/升级使用说明.md)。

## Windows 安装

从[知意 v0.5.0 Release](https://github.com/ha123-png/zhiyi/releases/tag/v0.5.0) 下载 Windows x64 安装包，并核对 Release 公布的 SHA-256。安装包不捆绑模型。

首次使用前，请连接本地 LM Studio/Ollama，或配置兼容云服务的 Base URL、模型名和 API Key。图片和扫描件需要支持视觉输入的模型。API Key 保存在 Windows 凭据管理器中，不应写入模板、日志或反馈内容。

## 数据与已知边界

- 默认业务目录为 `%LOCALAPPDATA%\Zhiyi`。普通卸载保留数据；选择卸载时清除数据会永久删除所选本地资料。
- 默认 API 只监听本机。没有正式身份和组织隔离能力，不应直接暴露到局域网或公网。
- 云端模型由其服务商处理请求内容；请核对服务商的数据政策。敏感材料可使用本地模型。
- 复杂版式、嵌入对象、扫描质量和提取准确度取决于文件、读取范围、模型和硬件。规则与人工审核仍是可信工作流的一部分。
- 当前仅提供 Windows x64 桌面版本；macOS/Linux 桌面发行版尚未提供。安装包未进行 Authenticode 代码签名，Windows 可能提示来源未知；请核对官方 Release 与 SHA-256，不要关闭系统安全防护。
- 知意不是 ERP 自动入账工具，也不应无人值守执行不可逆业务操作。

## 本地开发

需要 Windows、Node.js、Python 3.12 和 [uv](https://docs.astral.sh/uv/)。

```powershell
git clone https://github.com/ha123-png/zhiyi.git
cd zhiyi
npm.cmd ci
uv sync --project apps/api --dev --python 3.12
npm.cmd run dev:safe
```

开发入口：Web `http://127.0.0.1:5180`，API `http://127.0.0.1:8010`；Worker 单进程，模型任务并发为 1。
